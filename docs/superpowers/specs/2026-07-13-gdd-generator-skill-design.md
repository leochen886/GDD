# GDD Generator Skill — Design Spec

**日期：** 2026-07-13
**状态：** 待审核
**版本：** v1.0

---

## 一、目标

创建一个可复用的 Skill，帮助用户（个人游戏开发者）通过对话式交互，生成**电子游戏 MVP 级别的游戏设计文档（GDD）**。

核心价值：**先逆向学 GDD，再正向写 GDD。**

---

## 二、双模式设计

```
用户触发 /gdd 或 "帮我写GDD" / "游戏设计文档" / "逆向一个GDD"
        │
        ▼
┌──────────────────────────────────────────┐
│  模式判断：用户说了游戏名但没有自己的想法？    │
│                                          │
│  是 → 模式 1「逆向」                       │
│  否 → 模式 2「正向」                       │
└──────┬───────────────────┬───────────────┘
       │                   │
       ▼                   ▼
  ┌─────────┐        ┌─────────┐
  │ 逆向 GDD │        │ 正向 GDD │
  │ （见第三） │        │ （见第四） │
  └─────────┘        └─────────┘
```

**触发方式：**
- 精确触发：`/gdd`
- 语义触发：包含"游戏设计文档""GDD""写个设计文档"等关键词
- 模式切换：用户说"逆向一下 XX 游戏"自动走逆向模式

---

## 三、模式 1：逆向 GDD

### 3.1 目的
用户说一个已有游戏名，AI 按 GDD 模板反推该游戏的设计文档，让用户直观理解「GDD 到底是什么」「每个章节在写什么」。

### 3.2 流程

1. 用户说游戏名（例："逆向一下《吸血鬼幸存者》"）
2. AI 基于训练数据 + 必要时搜索补充信息
3. 按 MVP GDD 模板（8 章）填入设计内容
4. 在每章末尾标注信息可信度：
   - 🔵 **已知事实**（公开信息/开发者访谈等）
   - 🟡 **推测设计**（基于游戏表现的合理推断）
5. 输出完整 GDD，并在文档开头附一段 **「阅读指南」**：解释 GDD 是什么、每个章节的设计目的、如何读这份逆向文档

### 3.3 示例交互

```
👤 用户：逆向一下《杀戮尖塔》
🤖 AI：（搜索/回忆）→ 按模板写出 GDD → 标注事实/推测 → 输出
```

### 3.4 注意事项
- 不要捏造不存在的设计——不确定的地方明确标 🟡
- 优先选知名度高的游戏（信息丰富，逆向质量高）
- 逆向文档末尾建议用户：「看完这份，要不要自己正向写一个？」

## 四、模式 2：正向 GDD（三阶段）

### 4.1 Phase 1 · 速描（1-2 轮）

用户大白话倒想法 → AI 提炼结构化速描：

| 提取项 | 说明 |
|--------|------|
| 一句话描述 | 游戏到底是什么 |
| 核心勾子 | 一句话卖点，为什么有人会玩 |
| 核心循环 | 玩家每分钟在做什么（微观循环） |
| 目标体验 | 玩家感受到什么情绪/状态 |
| 游戏类型 | 细分品类 |
| 参考作品 | 对标/灵感来源的游戏 |

输出速描卡给用户确认，确认后进入 Phase 2。

### 4.2 Phase 2 · 搭骨架（逐章对话）

**首先**展示 MVP GDD 大纲（8 章），让用户确认/增删/跳过章节。

**然后**逐章对话填充，节奏原则：
- **每次只问一个问题**
- **关键决策给选项**（如核心乐趣来源、视角选择等）
- **将用户的大白话翻译为设计语言**，写成段落后回给用户确认
- **用户随时可说「跳过」「这章先过」**
- 深度由用户控制：核心玩法可聊 5 轮，数值框架可能 30 秒过

#### MVP GDD 模板（8 章）

```
1. 游戏概述
   一句话描述 | 核心勾子 | 目标平台 | 对标作品 | 游戏类型

2. 核心玩法
   核心循环图（文字描述） | 玩家每分钟在做什么 | 核心乐趣来源
   （必要时分开描述内层循环和外层循环）

3. 游戏系统（MVP）
   核心系统列表（战斗/交互/成长/经济等） | 每个系统的 MVP 范围

4. 关卡 & 内容（MVP 范围）
   几个关卡/地图 | 内容量是否够验证核心循环

5. 数值框架
   核心数值表 | 难度曲线方向 | 经济平衡基调

6. UI/UX 框架
   核心界面流程图 | HUD 关键信息 | 交互描述

7. 世界观 & 美术方向
   世界观一句话 | 视觉风格关键词 | 参考美术/情绪板

8. MVP 范围清单
   ✅ MVP 内 · ❌ MVP 外 · 🔮 以后再说
```

### 4.3 Phase 3 · 打磨

- 全局一致性检查（术语统一、系统间逻辑自洽）
- 发现遗漏 → 补充
- 输出最终 `项目名-GDD.md`
- 末尾附「待设计清单」：MVP 之后下一批要设计的内容

## 五、Skill 文件结构

```
.claude/skills/gdd-generator/
├── SKILL.md              # Skill 主文件
├── templates/
│   └── mvp-gdd.md        # GDD 输出模板（正逆向共用）
└── examples/
    └── sample-gdd.md     # 完整范例 GDD（给 AI 做写作参考）
```

**SKILL.md 核心模块：**

| 模块 | 内容 |
|------|------|
| 元信息 | skill 名称、描述、触发条件 |
| 模式路由 | 如何判断用户意图（逆向 vs 正向） |
| 模式 1 指令 | 逆向 GDD 的流程、标注规范、阅读指南模板 |
| 模式 2 指令 | 三阶段流程、对话节奏规则、每章引导问题 |
| MVP 铁律 | 贯穿全程——"够 MVP 就停"，防止过度设计 |
| 输出规范 | Markdown 格式、文件命名、编码等 |

## 六、设计原则

1. **一问一答**：每次只问一个问题，不给用户认知负担
2. **关键选择给选项**：不确定的地方给 ABCD，开放式细节让用户自由发挥
3. **翻译而非创作**：AI 的角色是把用户的大白话翻译成设计语言，不是替用户做设计决策
4. **MVP 铁律**：反复提醒"够用就停"，防止 scope creep
5. **先逆向再正向**：新用户建议先逆向看一个已有游戏的 GDD，建立认知后再正向写自己的
6. **全中文**：Skill 指令和产出的 GDD 均为中文

---

## 七、边界 & 不做的事

| 不做 | 原因 |
|------|------|
| 不生成可运行代码 | GDD 是设计文档，不是技术实现 |
| 不画 UI 原型图 | 可用文字描述 + ASCII 流程图代替 |
| 不做市场分析/商业化预测 | 超出 GDD 范畴（那是发行文档） |
| 不替代用户做设计决策 | AI 提供选项和框架，决策始终在用户手里 |
| v1 不做游戏类型路由 | MVP 用统一模板；类型差异化放到 v2 |

---

## 八、后续迭代方向（v2+）

- 按游戏类型提供差异化模板（RPG / 动作 / 策略 / 模拟经营等）
- 生成可交互的 Markdown + Mermaid 流程图（核心循环图可视化）
- 导出 Word/PDF 选项
- 逆向模式支持指定深度（"只逆向核心玩法" vs "全量逆向"）
